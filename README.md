# ふところ町（ふところまち）

自分専用の、資産・奨学金・支出・サブスクを見守る小さな町。

- **資産が主役**：銀行・投資（NISAなど）・奨学金の「確認した残高」と、その基準日を記録して、管理上の純資産を追う。
- **月末の確定**：月末の終了時点の実残高がそろった月だけを確定し、確定した月どうしで正しく比べる。
- **支出は気軽に**：金額とカテゴリーだけで記録。自分で付ける「★ ごほうび」と、自動で並ぶ「大きな出費」で振り返る。
- **サブスク荘**：1契約＝1部屋。内見（無料体験）・入居・退去。見込みと、実際に払った記録を分ける。
- **データはこの端末の中だけ**：サーバーなし・ログインなし。手動の JSON バックアップでドライブ等に保管する。
- **Galaxy Z Fold 向け**：閉じた画面（カバー）は片手で使える1段、開いた画面は左のメニュー＋2段組み、
  半分折ったフレックスモードでは入力シートが下半分（本の形なら右半分）に入る。
- **昭和レトロの町**：提灯（確定した月の数だけ灯る）、屋根で昼寝する猫、消印の確認日、朱の判子、通帳、レシート、
  ごほうびのシール帳、外階段つきのサブスク荘。

日々の利用は完全無料です（GitHub Pages で配信する静的なファイルと、ブラウザの保存領域だけで動きます）。
Claude の契約や API は使いません。金融機関の ID・パスワードも扱いません。

設計の判断は [docs/DESIGN.md](docs/DESIGN.md)、受け入れ条件の検証結果は [docs/VERIFICATION.md](docs/VERIFICATION.md) にあります。

## 1. GitHub Pages に置く（はじめに1回）

> **注意：GitHub の無料プランでは、Pages は「公開（public）リポジトリ」でしか使えません。**
> このリポジトリは現在 private です。無料で使うには、リポジトリを public にしてください
> （公開されるのは画面のプログラムだけです。入力したデータはリポジトリにも公開サイトにも入りません）。
> private のまま使うには GitHub Pro などの有料プランが必要です。

1. **Settings → General → Danger Zone → Change repository visibility** で public にする（無料で使う場合）
2. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. **Actions → Deploy to GitHub Pages → Run workflow** を押す（以後は既定のブランチへ push するたびに自動で動きます）
   - 単体テストに通ったら `app/` フォルダーだけが公開されます。数分かかります
   - 既定のブランチ（Settings → General → Default branch）から公開します。名前は `main` でなくても動きます
4. 公開先：`https://fubukiandkogure.github.io/money/`
   （同じドメインの `/subseat/` とは保存場所もキャッシュも別なので、旧サブスク荘は壊れません）

スマホのブラウザで Settings が見つからないときは、ブラウザのメニューから「PC版サイト」にすると出てきます。

#### 404 になるとき

- **Pages の公開先が 404**：上の 1〜3 がまだか、Actions の実行が終わっていないか失敗しています。
  Actions の画面で「Deploy to GitHub Pages」に緑のチェックが付くまで待ってください。
  赤い×なら、その実行を開いて「Re-run all jobs」（1〜2 を済ませる前に動いた実行は失敗しています）。
- **リポジトリ自体（github.com/fubukiandkogure/money）が 404**：private のリポジトリは、ログインしていないブラウザからは 404 に見えます。

### 更新するとき

`app/` の中を直して既定のブランチに push するだけです。開いている画面は、次に開いたとき（オンラインなら通常すぐ）新しい版になります。

- 画面のファイルを増やした・名前を変えたときは `app/sw.js` の `SHELL` の一覧も直します（`npm test` が漏れを教えてくれます）。
- 版を上げるときは `app/js/core/constants.js` の `APP_VERSION` と `app/sw.js` の `VERSION` をそろえて上げます。
- データの形を変えるときは `SCHEMA_VERSION` を上げ、`app/js/core/backup.js` の `MIGRATIONS`（バックアップの移行）と
  `app/js/data/store.js` の `upgrade()`（端末内データの移行）に手順を足します。

## 2. Android で使い始める

1. Chrome で `https://fubukiandkogure.github.io/money/` を開く
2. メニュー（︙）→「ホーム画面に追加」（または「アプリをインストール」）。追加しなくても使えます
3. ホームの **「はじめの準備をする」** で、よくある組み合わせ（給与の口座・貯金の口座・NISA・奨学金）をまとめて登録
   - 名前は自由に変えられます（銀行名を入れても入れなくても大丈夫）。使わないものはチェックを外します
   - 奨学金の「当初の元金」は分かる場合だけ（分からなければ空欄。返済率を作り話にしません。分かると「奨学金の坂道」が見られます）
   - 「先月末の残高から」を選ぶと、続けて先月末の残高をまとめて入力し、そのまま月末を確定（朱の判子）できます
   - 毎月の振替（給与→貯金）・NISAの積立・奨学金の返済・給与を「いつもの動き」として用意できます（記録は任意）
4. 毎月の流れ：月が変わったら、ホームの「◯月末の残高をまとめて記録」から4つの口座の月末残高を入れて確定
   - **基準日** は「その金額が表す日」。10/5 に 9/30 の残高を見たなら、基準日は 9/30
   - 月末の終了時点の値（金融機関の履歴・月末の評価額）を入れてください
   - 1つずつ記録・訂正したいときは **資産** の通帳から
5. 支出は「＋ 支出」から、金額とカテゴリーだけで記録（開いた画面では左のメニューの一番上）
6. 振替・積立・返済を記録したいときは **記録** の「いつもの動き」から1タップで呼び出せます
7. **サブスク荘** で、使っているサービスを1つずつ「入居」させ、月に1回ほど「支払った」を押す

### 数字の意味（大事なところ）

- **管理上の純資産** ＝ 銀行＋投資 − 奨学金の元金。財布・電子マネー・カードの未払い分などは含みません。
- 各口座の「最新の確認済み残高」の合計です。確認日がばらばらのときは、その旨を表示します（同じ日の総額ではありません）。
- 支出・入金・返済を記録しても、残高は自動では変わりません。残高は確認した値を記録したときだけ変わります。
- 支出の合計は **記録済み支出**（記録していないものは含みません）。記録のない月は「記録なし」で、0円や節約とは扱いません。
- 給与の口座の残高も、アプリの中では「自由に使えるお金」とは表示しません（引き落とし予定のカード代などを含まないため。仕様書の決まり）。
- サブスクの月額・年額は **見込み**（今の契約条件の換算）です。実際に払った記録とは別です。

## 3. バックアップと復元

データはこの端末のこのブラウザにだけあります。ブラウザのデータ削除・端末の紛失や故障に備えて、ときどき書き出してください。

### 書き出し

1. 右上の歯車 → **設定・データ**
2. 「JSONを書き出す（ダウンロード）」→ `futokoro-machi-backup-YYYYMMDD-HHMM.json` がダウンロードされます
   （「共有して保存」を使うと、Android の共有シートから Google ドライブなどへ直接渡せます）
3. そのファイルを **Google ドライブなど端末の外** に保管します
   - 画面の「最後に書き出した日時」は、ダウンロードや共有の操作をした日時です。ドライブへの保存が終わったかはアプリには分からないので、保存先で確認してください
   - ファイルには本人の金融データが入っています。人に送らないでください

おすすめのタイミング：月末の確定のあと、口座や契約を大きく変えたあと。

### 復元（別のスマホ・別のブラウザへ移す、壊れたときに戻す）

1. 移した先で `https://fubukiandkogure.github.io/money/` を開き、**設定・データ → 復元（置き換え）→ ファイルを選ぶ**
2. ファイルの中身が検証され、今のデータとファイルの件数が並びます（この時点では何も書き換えません）
3. 必要なら「今のデータを先に書き出す」
4. 「置き換わることを理解しました」にチェック →「置き換えて復元する」
5. 復元後、保存された内容から集計し直して、書き出したときの集計と一致したかが表示されます

- 復元は **置き換え** です（今のデータとファイルを合わせることはしません）。
- 壊れたファイル・別のアプリのファイル・新しすぎる版のファイルは読み込まず、今のデータは変わりません。
- 置き換えの途中で失敗した場合も、今のデータはそのまま残ります。
- 端末内のデータが読み込めなくなった場合は、エラー画面から「バックアップから復元…」で置き換えられます（データを勝手に初期化することはありません）。

### デモ

設定の「デモを別のタブで開く」（`?demo=1`）で、架空のデータを入れた見本を試せます。本人のデータとは別の保存場所です。

## 4. 手元で動かす・テストする

必要なもの：Node.js 22 以上（テスト用。アプリ自体は依存なし）。

```sh
node tests/serve.mjs          # http://localhost:8080/money/ で開ける（GitHub Pages と同じパス）
npm test                      # 計算・検証・配信物の単体テスト（依存なし）
npm run e2e                   # ブラウザでの受け入れ確認（Playwright と Chromium が必要。Fold の画面サイズ・半分折りも確認）
node tests/tools/fold-shots.mjs  # Fold の閉じた画面・開いた画面（縦横）で全画面を撮る（デモの架空データ）
npx eslint app tests          # 静的チェック（任意）
```

Node がなくても、`app/` フォルダーで `python3 -m http.server` を実行し `http://localhost:8000/` を開けば動きます。

## 5. 構成

```
app/                     公開されるもの（これだけが GitHub Pages に載る）
  index.html  manifest.webmanifest  sw.js  css/  icons/
  js/core/               計算と検証（金額・日付・資産・月末確定・支出・サブスク・バックアップ）
  js/data/store.js       端末内保存（IndexedDB）
  js/ui/  js/views/      画面
tests/unit/              単体テスト（受け入れ条件 A/E/S/D の計算部分）
tests/e2e/run.mjs        ブラウザでの受け入れ確認
docs/DESIGN.md           採用した詳細設計と理由
docs/VERIFICATION.md     検証結果と、確認できていないこと
.github/workflows/       テストと GitHub Pages への公開
```

外部への依存：配信に GitHub Pages、公開の手順に GitHub Actions（public リポジトリなら無料）。
画面のプログラムは外部のライブラリ・API を読み込みません（Content-Security-Policy で自分のファイルだけに制限）。
書体（Zen Maru Gothic・Zen Antique、SIL Open Font License）は `app/fonts/` に同梱しています。使う文字を含む分割ファイルだけが読み込まれ、一度読んだものはオフラインでも使えます。

## 6. 制限

- 自動同期・自動バックアップ・クラウド認証はありません（スマホやブラウザが違えば別のデータ）。
- 残高の照合（予測残高・未照合差額）、返金・立替・按分、カテゴリーの変更、予算や節約の判定は未対応です。
- 実機の Galaxy Z Fold・iOS/Safari では未検証です（Chromium で Fold 相当の画面サイズと折り目を再現して検証しています）。
